# 创建与维护 Skill

当用户要求创建、修改或检查仓库内的 skill 文档时，使用本 skill。

## 文件位置

- 每个 skill 必须独立存放在 `~/workspace/groot-cli/skills/<skill-name>/SKILL.md`（需要补充深层排障或专项参考时，可在同一目录下拆分同级 `.md` 文件并从主文件按需引用）。
- 全局 `~/.config/opencode/skills` 已软链至该目录，不要在外部目录重复创建副本。

## Frontmatter 规范

文件顶部必须以 `---` 包裹 YAML 元数据，且仅包含以下字段：

- **`name`**：仅限小写英文字母与连字符 `-`，必须与所在目录名完全一致。
- **`description`**：使用中文说明**何时触发使用**该 skill（而非仅罗列功能），长度不超过 `50` 个字符。

## 正文规范

- **语言与篇幅**：正文使用中文（参数名、字段名、路径、URL、环境变量与专有名词保留原文）；单个文件总行数不超过 `150` 行（含 frontmatter 与空行）。
- **禁止写具体代码与具体命令行**：正文中不得编写具体实现代码、调用脚本片段或完整命令行语句（无论是代码块还是行内命令串）。工具签名与命令行用法在运行时动态发现，避免硬编码在文档中产生漂移。
- **保留关键参数数值**：可以且应当明确写出关键参数名称、默认值、单位、取值范围、大小上限、超时阈值、关键路径、环境变量与返回状态码约定。
- **内容重心**：优先描述职责边界、前置检查、执行顺序、安全约束与失败处理，不写冗长背景介绍，也不穷举可动态查询的接口列表。
- **安全要求**：严禁在文档中写入真实的密码、订阅地址、token、secret、uuid 或私钥。

## 工作流程与完成检查

1. 明确该 skill 负责的任务范围与不处理的边界（指引越界需求转向对应 skill）。
2. 选定简洁的英文连字符目录名，编写 `SKILL.md` 及必要的同目录参考文档。
3. 核对检查项：
   - Frontmatter 位于首行，`name` 与目录一致，`description` 含触发时机且不超过 `50` 字。
   - 文件总行数不超过 `150` 行。
   - 文档内不包含任何具体代码块或具体命令行调用语句。
   - 关键参数默认值、范围、路径与实际实现一致，未虚构参数且无敏感信息。
4. 修改完成后提醒用户重启会话以加载更新后的 skill。
